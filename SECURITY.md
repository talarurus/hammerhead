# Hammerhead Core scope and security review

Native Core security acceptance for this `0.2.0-core.1` prerelease passed all 225 top-level tests on Apple Silicon macOS 27.0.1, including the required socket tests. The current distribution decision is **READY FOR EXPLICIT UNSIGNED PRERELEASE APPROVAL**. No Developer ID signature or notarization is present, and Gatekeeper acceptance remains unqualified. See `release/RESULTS.md` and `release/DISTRIBUTION-REVIEW.md`. No earlier macOS minimum, Intel macOS or Linux release is qualified. Publication still requires founder approval.

The original full-Git release remains subject to **A1-003 OPEN** and **original B4 BLOCKED**. Core does not resolve, waive or reclassify them, and does not qualify R1G/R1I or their Git path. The protected checkout, candidates, labs and prior evidence are untouched.

Core includes FILE-001, FILE-002, SEC-001, PROJ-001, PROJ-002 and textual GIT-001. **GIT-002: NOT EVALUATED.** There is no Git metadata collector package, Git health implementation, subprocess import or command registry path in Core. The dependency audit rejects `os/exec` and the full-Git package in the command graph; source checks inspect all local production variants, and live executable tests use a working fake Git/helper sentinel with positive controls. The MIME classifier imports `net/http` only for `DetectContentType`; Core makes no network calls. No credential validation, history scanning, full repository security, dependency vulnerability scan, entropy scan, effective ignore evaluation or legal license evaluation is promised.

Native safety remains the reviewed implementation: pin a root descriptor for the full native scan; derive traversal/read handles relative to it; reject out-of-root symlinks and unsupported types; nonblocking/no-follow opens and identity/type checks before reads; bounded directory inventory, aggregate reads, matches, findings and diagnostics; detect eligible-path and content mutations as incomplete required work. The root selected at establishment remains authoritative even if its pathname or alias is replaced. In-root symlinks may resolve to eligible regular files. Special files are policy skips, never read as content.

This is a live filesystem inspection, not an atomic snapshot. Detection of supported patterns cannot establish credential activity, pairing, exposure or compromise. Absence of findings means no supported finding in the declared policy, not absence of secrets. SEC-001's content eligibility is at most 5 MiB; binary, oversize, excluded and safety-rejected content is outside that promise. GIT-001's required parse/read failures remain partial; the root `.gitignore` heuristic cannot prove effective Git behavior. Runtime detection recognizes filenames and never executes project code.

Security evidence is redacted; JSON preserves structured paths while terminal/control diagnostics are sanitized and bounded. Reports still contain paths, titles and classification context. Output failures exit 2; `--quiet` and `--fail-on none` never suppress incompleteness. Cancellation preserves prior findings and reports cancelled/2.

Qualification uses only disposable synthetic fixtures, including mutations, symlinks, special files, resource failures, sentinels and report attacks. Excluded full-Git tests are enumerated in `release/ACCEPTANCE.md` and are not counted as passing Core tests. Source and module hashes identify this candidate; hashes provide provenance and integrity comparison, not publisher authentication. Developer ID signing, notarization, Gatekeeper/quarantine validation and earlier-macOS support remain unqualified and are explicitly disclosed for the unsigned approval option. Founder distribution approval is pending.
