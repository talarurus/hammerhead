# Claims Ledger

This ledger records architectural and textual claims present in Hammerhead that are over-strong, inaccurate, or misleading, to be corrected in later implementation phases.

| Current Claim / Text | Why it is over-strong / misleading | Exact Source Location | Accurate Replacement / Direction | Phase | Test to enforce |

| SEC-001 "committed" wording | Says secrets are "committed to repository" even for uncommitted files in a dirty worktree. | `internal/check/secrets.go` findings | Change to "present in file" or use working-tree versus committed-file terminology. | Phase 1 (Catalogs) | `TestCatalog_WorkingTreeTerminology` |
| SEC-001 "corresponding" AWS credentials wording | The scanner just asserts that an ID and a Secret exist in the *same file*. It does not verify that the secret mathematically corresponds to the ID. | `internal/check/secrets.go` | "An Access Key ID and a Secret Access Key assignment were found in the same file." | Phase 1 (Catalogs) | `TestCatalog_AWSCooccurrenceText` |
| Filename evidence versus verified secret contents | FILE-001 titles like "SSH private key" imply the file actually contains a private key, but it's just a filename match. | `internal/check/sensitive_files.go` | Emphasize "filename indicates" or "Potential SSH private key file". | Phase 1 (Catalogs) | `TestCatalog_FILE001Claims` |
| FILE-002 "committed file" language | Says "Large file committed" even for untracked/uncommitted files. | `internal/check/large_files.go` | Use "Large file present in working tree". | Phase 1 (Catalogs) | `TestCatalog_WorkingTreeTerminology` |
