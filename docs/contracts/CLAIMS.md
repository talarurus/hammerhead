## C15 integrated reconciliation

The acceptance index in [ACCEPTANCE.md](ACCEPTANCE.md) maps each frozen gate to executable evidence. This is a review candidate, not a published release. Development defaults in CLI, JSON reporter and Makefile are `0.2.0-dev`. Only the version value in the four active v0.2 reporter goldens follows this default; historical v0.1 captures and the separate design fixtures remain unchanged. Current clones/imports use Talarurus; the original v0.1.0 assets/module/tag and historical fixtures remain intact. README's automation example writes outside the scanned root and returns the saved scanner status.

The G7 descendant-pipe test previously started a 200 ms deadline before its race-instrumented helper/child initialized, and once failed because `.child_pid` did not yet exist. C15 uses a pipe acknowledgement from the locked descendant, a published readiness barrier and explicit parent release. Only then does the leader exit and Go's pipe WaitDelay exercise the timeout/cleanup path. Separate existing timeout/cancellation/force-kill/stubborn-descendant assertions remain. No production process-cleanup logic was changed.

Integrated boundary tests exposed float size parsing that lost integer precision and accepted overflowing values as MaxInt64. Exact standard-library decimal arithmetic now checks range before int64 conversion and preserves units/fractional-byte truncation. This changes argument validation at numeric boundaries, not detectors or default thresholds. Policy telemetry now reports applied exclusions/traversal/Git budgets and known zeros; status, IDs and finding content remain unchanged. Setup/cancelled scans never use zero observations as evidence of absence.

`ROADMAP.md` is intentionally byte-preserved under the frozen-roadmap restriction. Its historical “confirmed ... pairs”, “verify ... properly excluded” and general safety phrasing are not current evidence claims: SEC-001 observes same-file patterns without validation/pairing, GIT-001 uses textual heuristics, and native defense in depth is not an OS sandbox. Current authoritative descriptions are this ledger, RULES, SCAN-RESULT, OUTPUT, ARCHITECTURE and the migration guide. Later roadmap features remain unimplemented; no Phase 2 scope or speculative API was added.

GitHub CI is configured for native Linux/macOS amd64 on explicit standard labels, minimum Go 1.26.0 and current `stable`, with formatting/vet/full/race/integrated tests and repeated descendant cleanup. Four CGO-disabled targets compile to temporary directories. Local arm64 runtime validation and pending remote CI are recorded separately; compile success never implies native runtime safety. No publishing, signing, deployment, credentials or privileged devices/runners were added.
